# ADR-001: Стратегия PII Redaction

| Field        | Value                                        |
|-------------|----------------------------------------------|
| Status      | **Accepted**                                 |
| Date        | 2026-11-14                                   |
| Related TM  | TM-02                                        |
| Related NFR | NFR-SEC-001                                  |

## Context

Система обрабатывает GitHub Issues и комментарии, которые могут содержать PII (email, телефон, ФИО, СНИЛС, ИНН, паспортные данные). Все данные должны быть очищены перед отправкой в LLM-провайдера (YandexGPT) в соответствии с 152-ФЗ.

## Decision

Принимаем **двухуровневую стратегию**:

1. **Presidio Analyzer** — основной движок распознавания PII (email, phone, name, credit card, и т.д.).
2. **Кастомные regex-паттерны** — для российских специфичных форматов, которые Presidio не покрывает out-of-the-box:
   - СНИЛС: `\d{3}-\d{3}-\d{2}\s\d{2}`
   - ИНН физлица: `\b\d{12}\b`
   - ИНН юрлица: `\b\d{10}\b`
   - Паспорт РФ: `\b\d{4}\s\d{6}\b`

PII заменяется на placeholder-ы вида `[EMAIL_REDACTED]`, `[SNILS_REDACTED]` и т.д.

## Consequences

- **Плюсы:**
  - Presidio покрывает международные паттерны.
  - Кастомные regex покрывают 152-ФЗ специфику.
  - Оба слоя логгируются (сколько PII найдено, какие типы).
- **Минусы:**
  - Presidio требует загрузки NLTK-корпусов.
  - Regex могут давать false positives (например, случайная последовательность цифр).
  - Нужно регулярно обновлять regex-паттерны.
