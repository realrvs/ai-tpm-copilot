## Why
Технические программы (TPM) тратят до 20% рабочего времени на ручной сбор статусов: чтение Issues, выявление блокеров, написание отчетов для стейкхолдеров. В условиях роста сложности проектов и количества репозиториев (например, 189 Issues в одном проекте) этот процесс становится узким горлышком, приводит к задержкам в коммуникации и пропуску критических рисков.

**Метрики проблемы:**
- Время на подготовку еженедельного статуса: ~4 часа/неделю.
- Задержка в выявлении блокирующих зависимостей: 2-3 дня.
- Человеческий фактор: пропуск 15% критических комментариев в Issues.

**Решение:** AI TPM Copilot автоматизирует сбор, очистку (PII) и анализ данных из GitHub с помощью LLM, генерируя готовый статус-репорт и карту рисков.

## What Changes
- Создание сервиса сбора данных из GitHub API (Issues, PR, Comments) с фильтрацией по датам.
- Внедрение модуля PII Redaction (152-ФЗ) перед отправкой данных в LLM.
- Разработка LLM-пайплайна для суммаризации статусов, выявления блокеров и категоризации задач.
- Генерация Markdown-отчета и интеграция с Telegram для доставки.
- Сквозная инструментация OpenTelemetry для мониторинга пайплайна (latency, токены, ошибки).

## Impact
- **Затронутые capabilities:** project-management, reporting, ai-analysis, data-privacy.
- **Затронутые команды:** TPM, Engineering Leads, Security/Compliance.
- **Целевые метрики:** Сокращение времени на отчет на 80% (с 4ч до 45 мин). Выявление 100% блокеров за 1 час вместо 2-3 дней.
- **Security-профиль:** Работа с внутренними данными проекта (возможны PII в комментариях), LLM-компонент (prompt injection, data leakage), соответствие 152-ФЗ.
